> **Goal:** a *comprehensive* catalog of the kinds of requests we expect, each mapped to its primary function and any secondary functions. This is the backbone of [[routing-and-functions|routing]].

## To design here

- The full enumerated list of request types (financial, facility, transportation, care/meals, communications/connection, administrative, events, etc.).
- For each type: primary function, possible secondary functions, default urgency, and whether it commonly needs elder involvement.
- The catch-all path for "unclear / multi-function / I'm not sure."
- How a multi-function request is split or co-owned.
