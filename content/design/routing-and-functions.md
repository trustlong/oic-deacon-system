> **Goal:** define how any request is navigated to a *specific person*, across the four functions, with a clear priority order for whom the responder contacts.

## To design here

- The intake → triage → assignment flow (who is the first responder, how they classify a request).
- The "resource priority pass": given a need, the ordered list of who to contact (member with the resource/skill → function co-worker → Associate Director → Director → Chairperson).
- How the four functions ([[handbook-administration|Administration]], [[handbook-operations|Operations]], [[handbook-communications|Communications]], [[handbook-finance|Finance]]) and their sub-lanes (Welcome, Kitchen, Coffee, IT, PEP, Security, Drivers) receive routed work.
- Multi-function requests: primary owner + collaborators.
- The link to [[resource-tagging]] — routing depends on knowing who can help.

## Draft routing flow

```
Request in (any source)
   → First-responder deacon acknowledges + becomes owner
   → Tangible? ──no──> redirect to Elders ([[escalation-to-elders]])
        │yes
   → Classify via [[request-taxonomy]]  →  primary function (+ secondary)
   → Resource priority pass: find the BEST specific person to help
   → Assign + set urgency/SLA ([[sla-and-urgency]])
   → Track to closure ([[crack-detection]])
   → Follow up + close
```
